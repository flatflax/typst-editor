# 交互设计与产品决策

复核：2026-10-23。本文定义产品范围、交互要求、适用条件和编号决策；实现及验收记录集中在 [Phase 4](phase4-product-validation.md)，当前排期见 [plan.md](../plan.md)。下文将“规范要求”“已有实现”“待验证/待设计”分开，规范不是测试通过声明。

## 1. 产品定位（5W1H）

| 问题 | 定位 |
|---|---|
| 为谁 | 已了解 Typst 的论文、报告及其他技术文档写作者，包含 CJK 用户 |
| 解决什么 | 在真实 Typst 排版与日常输入之间减少切换、定位和结构操作成本 |
| 在哪里 | 本地桌面、单文档工作流，直接读写 Typst/Markdown |
| 如何实现 | 未聚焦内容显示真实编译结果；聚焦块使用原生源码文本框；结构命令复用文档变换 |
| 当前阶段 | 机制已有实现与工程验证，独立目标用户验证尚未开始 |
| 长期目标 | 逐步接近最终排版内的直接编辑；不承诺当前已完成完整所见即所得 |

不再以“用户完全不接触语法”为目标。Markdown 是一等文件格式，不只是交互参考。协作不在既定范围，AI 功能不在近期范围。

## 2. 用户定位

核心用户愿意使用 Typst 源码，但希望更容易浏览和修改排版文档；不以完全不了解标记语言的用户替代这一定位。

仍需验证：用户是否把真实渲染视为主要需求，是否接受整块源码编辑，以及与源码加预览相比是否获得实际收益。当前开发者手动测试不能替代这些结论。已明确的用户反馈是 Live cursor 编辑后预览慢，应按整体更新路径处理。

## 3. 用户需求分析

可靠输入、撤销、保存、定位与结构修改是前提；公式、文献引用/参考文献、脚注是学术写作的重要能力，尚无完整专用交互。

CJK 分开考虑：原生输入法的组合、候选窗和编辑行为由输入系统负责；字体覆盖、标点、缩进等排版质量由 Typst、模板及字体共同决定。支持中文输入不等于解决了全部 CJK 排版问题。

## 4. 差异化竞争力

当前可验证的特点是：未聚焦内容来自真实 Typst 编译，常规单块输入使用原生控件，结构操作仍能通过工具栏执行。聚焦时显示源码，不是最终排版内直接编辑，因此完整所见即所得保留为长期愿景。

2026-09 的竞品调查仅提供设计参考，不作为持续更新的产品能力排名，也不证明市场唯一性：

| 参考 | 可借鉴之处及证据边界 |
|---|---|
| Typora、Notion | 减少模式切换，显式结构操作与命令发现；不照搬所有标记语法，特别是 Markdown 标题语法与 Typst 不同 |
| Typst Web、双向同步编辑器 | 预览定位与源码定位；同步能力本身不等于单面直接编辑 |
| Underleaf | 视觉编辑仍需长期积累语义与结构能力；其近似编辑面与最终输出应分别评估 |
| TyX、Typstudio、Katvan | 分别参考早期数学控件、工程尝试与双向定位；不能由早期项目状态推断当前完整 Typst 编辑能力 |
| TeXmacs | 明确数学/结构编辑边界，避免让用户误判当前可编辑内容 |
| JetBrains MPS | 文本输入与结构操作可以互补；不要求为所有语法新增专用控件 |
| Monaco 等代码编辑器 | 输入与异步语义工作分离；组合和导航不能依赖每键同步后端查询 |
| SwiftLaTeX 等 LaTeX 编辑器 | 参考在真实排版中编辑的目标；相关产品术语不作为正式行业定义 |

历史调查还提示：Typst 的可编程性与 GUI 操作存在范围取舍；不能由论坛意见直接推出目标用户的实际选择。Google Docs 等产品的增量显示仅作为方向参考，本文不据二手资料断言其内部实现。

这些参考分别影响不同决策：[TeXmacs](https://www.texmacs.org/joris/gut/gut.html)用于检查编辑模式边界是否清晰；[Notion 的命令交互](https://www.notion.com/help/guides/using-slash-commands)用于评估功能发现，不构成 Live cursor 必须有斜杠菜单的依据；[Typst Web 预览](https://typst.app/docs/web-app/export-and-preview/)用于区分双向定位和最终排版内编辑。这里只保留既有研究的用途，不将其描述为 2026-10-23 的重新核实结果。

## 5. 产品化缺口与验证方向

### 内容与语义

无直接可见几何的构造至少分为三类：变量/规则/标签需要定义及影响范围定位；注释与未知语法需要源码保留；公式等高频可见内容才适合逐步提供结构编辑。不能统称“显示源码即可”。

现有使用端到定义端导航不等于引用/参考文献管理。多文件导入、作用域、样式影响范围及反向引用仍有缺口。结构化转换支持的子集也不等于 Typst 全语言支持。

### 编辑体验

单块依赖原生控件，跨块仍需自绘选区、隐藏输入及历史交接；必须覆盖输入法、剪贴板、上下移动、异步焦点与错误恢复。多页裁剪、几何近似和显示占位均可能直接影响编辑体验。

应分别测量：

1. 输入到原生文本变化的响应。
2. 提交到编译结果返回。
3. SVG 传输、DOM 更新、首次绘制及邻块稳定。

历史编译微基准只能解释第二项的一部分。临时源码提示也不能替代真实预览更新。

### 需要验证的假设

核心交互接受度、整块源码范围是否合适、自动保存/恢复预期、四个 tab 收敛后的源码入口、学术写作优先级。此前否定的是特定混合布局实现，不应将一次工程实验扩大为某类交互永远不可实现。

## 6. 核心交互机制：聚焦块编辑源码

### 6.1 数据、状态与基本约束

区分已提交源码、聚焦块草稿、最后成功编译的源码/结果，以及最新诊断。四者可能暂时不同：输入改变草稿；提交改变编译输入；成功编译才推进显示结果。保存读取草稿，并不要求先改变显示状态。

| 状态 | 用户看到什么 | 输入及位置依据 | 实现边界 |
|---|---|---|---|
| 未聚焦/组合视图 | Typst 编译结果；跨块选择可有自绘选区 | 与显示结果匹配的源码字节范围和几何 | 不能拿尚未显示的新源码几何解释旧像素 |
| 单块聚焦 | 整块原始源码，等宽字体与明显背景 | 原生 textarea 的 UTF-16 光标、选区、输入法与局部历史 | 聚焦粒度为整块；不是最终排版内的直接输入 |
| 组合输入中 | 原生输入法组合文字与候选 | 原生组合事件和独立 composing 状态 | 单块原生输入已有基线；跨块隐藏输入的实时组合反馈仍不完整 |
| 提交/重新编译中 | 明确的临时提示或尚未更新的成功结果 | 交互必须等待对应版本或保留在原生草稿 | 占位是等待反馈，不能伪装成新的最终排版 |
| 编译失败 | 最新诊断、错误块源码和上次成功结果 | 原始输入继续保留；旧结果只配旧几何 | 无成功结果、多错误与块数变化仍需验收 |

不产生可见墨迹的声明也必须有源码访问路径。当前已有定义跳转与全文源码入口；零高度裁剪不等于已经提供可发现、完整的声明编辑界面。

### 6.2 聚焦、失焦与直接切块

1. 点击渲染内容时解析目标位置，准备聚焦及邻居的几何，再切换显示；不要先显示错误尺寸、下一帧再纠正。
2. 聚焦时显示原始文本，不自动全选。普通点击入口当前通常把光标放在块末；命令/导航可指定位置。点击像素到 textarea 精确插入点尚不作为已完成保证。
3. 聚焦宽度和边距与页面内容范围对应；窗口宽度变化后重排，不重挂载输入，不丢失草稿或原生历史。短内容不应出现多余滚动条；超过 60vh 时允许内部滚动。
4. 文本框失焦或非组合状态下 Escape 均提交草稿，Escape 不承担额外的丢弃语义。未修改的聚焦/失焦不应产生历史步骤或 dirty。
5. 直接点击其他块时，先保存原块草稿，再按提交后的字节位置找目标，不能沿用已被空行拆分改变的块索引。最终焦点应属于最后一次有效点击，不能被较早的异步结果覆盖。
6. 工具栏和定义按钮阻止 mousedown 的默认夺焦点，由操作处理草稿；避免 blur 提交/卸载抢在 click 前发生。这不等于禁止正常 Tab 离开输入框。

旧设计要求窗口/App 失焦也提交。当前源码明确连接的是 textarea 的 DOM blur，未看到独立窗口失焦监听；**切应用、最小化、返回时的提交/草稿保留需原生验证**。不能只凭旧规范认定所有系统失焦都等价于 DOM blur。

### 6.3 换段、清空、粘贴与未知构造

采用失焦后分块：用户在聚焦块内可以输入空行或粘贴多段文字，输入途中不拆走已完成部分，不因此反复卸载输入和闪烁邻块。提交后才依据源码边界重新分块。未采用逐空行立即拆分，是因为实验出现连续写作中的反复 pending，而非因为实时解析在技术上不可做。

| 输入 | 规范期望 | 当前实现或缺口 |
|---|---|---|
| 顶层普通段落之间空行 | 提交后可形成多个块；后文及引用位置保持正确 | depth-aware 空行扫描已有实现，不是完整语法树分段 |
| 表格、figure、多行函数内部空行 | 不拆断同一语法构造 | 括号、字符串、注释、单反引号有保护；三反引号围栏仍有缺口 |
| 清空一个块 | 草稿和删除意图保留；提交不留下旧内容，不删除邻块 | 当前为文本范围替换，再重新分块；零长度范围/文档全空的焦点结果需验收，不能声称已有完整空块删除模型 |
| 清空整个文档 | 空文档仍可输入、保存、撤销，不因缺少几何而卡住 | PM 结构命令可能因空位置映射不适用；这是命令边界，不应吞掉源码 |
| 有效但未建模的语法 | 原始片段可编辑；未修改时不得静默改写 | 原始节点保留；模型重建和跨格式转换另有边界 |
| 暂时不合法的语法 | 保留全部输入，显示诊断；修复后恢复编译 | 不自动补括号或删除失败文本；不能拿不支持的结构当作语法错误 |

未知语法的不可退让要求：不删除、不静默改写、保持原始片段；未建模构造不应仅因有空行被当成普通段落切碎。结构化工具不得把读不懂的内容擅自转成可部分编辑的表格/列表。当前工具栏执行整篇 parse→transform→serialize，不能承诺文档中所有未操作部分的字节完全不变；新增真实样例和操作前后比较后，才可扩大保真声明。

原格式直接保存草稿与经过模型/另一格式转换是两条不同路径。GFM 列宽与图片题注损失必须在跨格式操作中解释，详见 [Phase 2](phase2-content-io.md#cross-format-losses-must-be-explicit)。

### 6.4 跨块选择与剪贴板

块内原生选择优先；拖出文本框时记录交接意图，不立刻把两套不同高度的布局来回切换。鼠标松开后提交草稿，等待 expectedSource 对应渲染且非 pending，再按最终坐标建立跨块选区。一次手势不能因为异步结果反复关闭/重开文本框；正向和反向拖拽遵循同一规则。

- 跨块选择用 UTF-8 字节范围，DOM 草稿用 UTF-16；CJK、emoji 及分隔空行均必须按实际源码处理，不能按显示字形数截取。
- 复制输出 text/plain 源码，不复制渲染后的纯文字或空隐藏输入值；空选区不改剪贴板。
- 剪切先写剪贴板，再删除范围；一次剪切是一项可撤销编辑，不能与随后输入合并。
- 粘贴替换实际选区且只插入一次；清理隐藏输入避免 input 路径重复插入。无 text/plain 的数据当前没有自定义富内容粘贴承诺。
- 块内剪贴板保留浏览器行为。跨块剪切/粘贴与真实 OS 剪贴板的集成仍需原生检查，DOM 模拟通过不等于该检查已完成。

### 6.5 键盘、输入法与历史

| 操作 | 规范及当前行为 | 未完成或需验证 |
|---|---|---|
| Enter | 聚焦源码文本框按原生规则插入换行；组合视图用两个换行表达 Typst 新段落 | 两种状态的差异应在实际文档验收，不应写成所有 Enter 都相同 |
| Up/Down | 先允许块内原生移动；折叠光标没有移动时跨到相邻块末/首 | Shift+Up/Down 跨块扩选未实现；候选选择期间不应触发跨块导航 |
| Shift 与鼠标选择 | 块内原生；组合视图按几何扩选 | 不承诺所有原生 Shift 手势都已接入跨块模式 |
| Ctrl/Cmd+Z、重做 | 聚焦时原生历史优先；下一帧确认无变化才交给应用历史 | 切文档隔离历史；历史内存预算及精确恢复旧光标仍未完成 |
| Ctrl/Cmd+B/I | 调用与工具栏一致的结构命令 | 需要选区；折叠选区没有持续 storedMarks，不应标为完整“后续输入带样式” |
| Ctrl/Cmd+S | 保存当前草稿，不为保存强制失焦或编译 | 由原生菜单加速键处理，避免 DOM 重复触发 |
| Escape | 非组合状态提交并退出源码块 | 组合候选优先取消/关闭，不应意外提交；当前键盘处理需原生 IME 验收 |
| Tab、切应用 | 不丢草稿，焦点顺序可理解 | 默认 DOM 焦点行为和系统窗口失焦分别检查 |

输入法组合数据是当前完整组合串，不可逐事件追加；composition 状态不能只信单个 input.isComposing。组合中暂停自动保存，结束后再开始保存计时。取消组合不应残留临时拼音，也不应产生双重提交。中文、日文候选切换和韩文逐音节周期分别验收；不能用合成事件替代全部真实输入法测试。

应用历史对短时间相邻输入可合并，对剪切/粘贴和结构动作保持操作边界。原生无效撤销后才回退，不能同时执行两套撤销。已知限制应保留为缺口，不能因单块 textarea 有原生撤销就认定跨块历史问题消失。

### 6.6 结构命令、定义导航与补全

结构操作先读取当前草稿和选区，再临时解析整篇文档、执行 PM 命令、序列化并恢复原生焦点。命令不适用时保持内容，不能把 no-op 显示为成功修改。带标记区域的位置映射仍近似，跨 CJK 前缀和嵌套标记需独立场景。

引用清单显示当前块实际用到的绑定/标签，点击到定义；无引用时不保留空清单。解析按作用域，而非查找第一个同名文本；标签跳到有标签的元素，未解析引用不制造错误跳转。当前不覆盖 #set 影响、反向使用列表及完整多文件项目。已有声明补全仅为设计，键盘菜单优先级和触发规则见决策 18，不计入已交付交互。

### 6.7 保存、文件切换与退出

保存和 PDF 导出包含未失焦草稿。已有路径的自动保存等待 2000ms 停顿和组合结束；无路径不能静默选择文件。手动与自动保存按请求顺序写入，失败保留 dirty 并允许重试，较早保存不能把随后输入或新文档标记为干净。

打开另一文件和退出先判断当前草稿。退出提示中“是”表示丢弃未保存改动并关闭，“否”表示保留当前文档；不得把“是”当作保存。SDK 确认后 destroy 需要主窗口权限。当前确认/取消有 SDK 流程回归，原生干净窗口关闭已检查，带改动对话框的新原生验收尚缺。

自动保存直写原文件不是独立恢复文件。崩溃恢复和保存方式的用户预期仍待验证，不能用“已有自动保存”承诺可恢复任意未保存输入。

### 6.8 诊断、等待反馈与验收场景

编译失败保留上次成功的 SVG 和对应源码；诊断始终来自最新尝试。错误块显示源码和错误，Locate 直接进入该块。冻结结果不是新文档的正确预览：全局错误未修复时，其他合法编辑也无法得到新的编译结果。无成功结果、多个错误、错误改变块数与页数均应作为独立用例。

下面的场景编号供 Phase 4 记录证据；它们是验收要求，不是本次执行结果。

| 编号 | 场景与预期 |
|---|---|
| UI-01 | 点击聚焦再离开而不输入：文本不变、不新增历史；宽度与裁剪无重复或错位 |
| UI-02 | 输入多段、整段粘贴、清空块及全文：提交后结构合理，邻块不丢，撤销恢复 |
| UI-03 | 表格/多行调用/未知语法含空行：不错误拆分，不静默重写原始内容 |
| UI-04 | 块 A 修改后直接点 B、再快速点 C：A 保留，最后焦点为 C；重复执行包含新空行的版本 |
| UI-05 | 向前/向后跨块拖拽，含 CJK/emoji：选区范围正确，无关闭重开循环；pending 不用旧几何解析新位置 |
| UI-06 | 复制/剪切/粘贴和紧接输入：源码准确、一次插入；剪切/粘贴可独立撤销/重做 |
| UI-07 | 中文、日文、韩文组合、取消、候选移动：原文不丢、无重复，中间文本不被自动保存 |
| UI-08 | Up/Down、Shift 扩选、Tab、Escape、切应用：遵守状态规则；尚未实现的跨块 Shift 不误标已支持 |
| UI-09 | 原生撤销耗尽后应用撤销、结构操作后撤销、打开新文档：不双重撤销，不泄漏旧历史 |
| UI-10 | 聚焦草稿保存/自动保存/导出、写盘失败、旧请求晚到：内容与 dirty 正确，焦点/历史不重置 |
| UI-11 | 有草稿时取消打开/退出、确认退出，以及无修改关闭：按提示语义执行，窗口实际关闭或保留 |
| UI-12 | 初次编译失败、成功后失败、多错误、块数变化及恢复：原文保留、诊断对应最新输入、旧几何不误用于新文本 |
| UI-13 | 同名绑定在不同作用域、标签、未定义引用：到正确声明，无错误跳转，不暗示已支持规则影响追踪 |
| UI-14 | 窄窗口、多页、后页聚焦和滚动：裁剪及光标正确、占位能更新、不滚回顶部；局部测试不覆盖全部排版 |
| UI-15 | 切目录、连续编辑与旧编译结果晚到：源文档、目录、结果一致；按页版本失败有完整重同步路径 |

## 7. v0.1 范围决策

保留本地文件工作流、Markdown 双向转换、独立 Typst 源码入口、原生块输入、结构工具栏、跨块操作、手动和自动保存、PDF 导出。

四个 tab 尚未收敛；收敛已列为本轮修复验收后的下一项主要工作，不等待公式专用控件或悬停高亮。当前建议为默认 Live cursor、保留 Typst/Markdown 源码入口并移除旧 WYSIWYG tab；**源码入口的界面形式、快捷键、切换和返回规则尚待设计与验收，不是已经确认并实现的完整规范**。Markdown 打开、保存与双向转换能力必须保留。

自动保存选用直接写已有原文件，2000ms 暂停后触发；未命名文件先手动保存。此方案复用现有文件路径，尚无用户数据证明优于独立恢复文件。未来增加恢复层不必推翻当前文件格式决定。

公式、引用/参考文献、脚注已确认提高后续优先级，尚未完成专用编辑。Live cursor 斜杠菜单待定，v0.1 不做；声明自动补全仅完成设计。原型代码保留供研究，不承担产品维护承诺。

## 8. 功能优先级与冲突原则

优先级与当前施工顺序分开：P0 是正确性底线；P1 是 v0.1 必须有的基本能力；P2 是值得投入但不能破坏 P0/P1 的扩展；P3 是未来方向或尚未排期。明确排除的协作不应混入“以后要做”清单。

| 优先级 | 能力与版本范围 | 当前状态/缺口 | 排序依据 |
|---|---|---|---|
| P0 | 未聚焦内容使用真实 Typst 渲染，贯穿版本 | 已有，错误期间明确保留旧结果 | 不引入第二套近似排版作为权威显示 |
| P0 | 单块原生输入与当前核心机制，v0.1 | 已实现；系统失焦与多页仍需验收 | 后续输入、保存及跨块操作依赖此机制 |
| P0 | 未知语法不丢失、不静默改写，v0.1 | 原始保留已有；结构操作与分块边界仍需样例覆盖 | 文档数据完整性先于便利功能 |
| P0 | 撤销/重做、基础快捷键，v0.1 | 原生与应用历史已有；无历史内存预算 | 编辑可逆；新命令不能破坏旧历史 |
| P0 | 原生 IME 组合反馈，v0.1 | 单块已有基线；跨块组合实时显示/候选窗尚缺 | 目标包含 CJK 用户，不能将乱码或组合丢失降为视觉瑕疵 |
| P0 | 保存/离开保护与错误恢复，v0.1 | 草稿保护和冻结结果已有；新原生错误/关闭场景待验 | 不丢输入，也不伪造更新成功 |
| P1 | 表格/列表/标记等结构编辑，v0.1 可先基础版本 | 工具栏已适配；折叠标记与近似映射仍有限制 | 与已有编辑能力对等，不为替换入口回退功能 |
| P1 | 跨块源码剪贴板，v0.1 | DOM 回归已有，真实 OS 待验 | 单块原生剪贴板不能覆盖跨块选择 |
| P1 | 自动保存与手动保存共存，v0.1 | 已有；独立恢复文件未做 | 减少丢失风险，同时保留主动保存 |
| P2，当前下一项 | 四个 tab 收敛 | 未实施；排在当前修复验收后 | 原生块机制不会自动移除旧入口，需独立设计和迁移 |
| P2，当前开放 | 编辑后预览性能 | 用户报告已确认；调度/按页代码开发中，未给整体加速结论 | 编译微基准不能代替用户实际等待时间 |
| P2 | 界面视觉整理、长文档大纲、就地诊断 | 范围/排期未完整确定 | 提升可发现性和长文档操作效率 |
| P2 | 文本层与无障碍访问 | 尚未实现；重点是渲染/跨块场景 | SVG 路径不自然提供文本语义，原生块输入不是全应用无障碍 |
| P2↑ | 公式、引用/参考文献、脚注及对应专用交互 | 2026-09-10 从 P3 提高；未实现完整专用控件 | 学术写作需要，原生源码机制降低部分实现门槛 |
| P2，暂停旧面投入 | 表格 hover 把手、拖拽列宽等精细交互 | 不继续独立打磨旧 PM 编辑面 | 待统一编辑面方向稳定，避免重复实现 |
| 待定 | Live 斜杠菜单 | v0.1 不做；不是已有功能 | 旧“完全免语法”理由不再成立，替代需求待用户验证 |
| 待排期 | 已声明变量/函数补全 | 仅完成设计，见决策 18 | 与实际引用导航不同，仍需取回全部可见绑定和菜单规则 |
| P3 | 模板画廊 | 长期方向，v0.1 不做 | 不阻塞基本编辑工作流 |
| 保留能力 | 独立源码入口、Markdown 格式 | Typst 源码保留是既有范围决定；Markdown 一等格式不变 | tab 的界面收敛不能变成格式能力删除 |
| 排除 | 协作；近期 AI 接入 | 不在当前路线范围 | 不将排除事项写成未完成缺陷 |

正确性优先于速度；新功能不能破坏撤销、输入法与保存。判断优先级依据用户可感知的收益和缺陷，不以工程量小替代需求判断。简单方案须保留升级路径；尚未验证的价值和取舍明确标为假设。

决策登记时同时保留提出时间、确认依据、实现位置及验证状态。23 条编号决策是结论索引，不能代替本节版本范围、§6 的行为规范或 Phase 4 的证据。后来修订结论时标明替代关系，不抹掉原先实验的目标和局限。

## 9. 当前能力边界

旧 WYSIWYG、Typst source、Markdown source 与 Live cursor 仍并存，旧视图仍默认。原生 Typst 编译、范围几何、分块裁剪、结构工具和文件闭环已具备；尚未形成统一产品入口。

后台已有增量源码编辑与缓存，默认前端仍接收整篇 SVG；工作区新增加了尚待原生验收的请求调度及可选按页差异协议。没有专用悬停高亮、声明补全、完整文献引用或多文件项目支持。原生格式文本保存与结构化格式转换的保真边界分别记录在 [架构](architecture.md)。

## 10. 结论与下一步

保留原决策编号，便于代码注释和历史引用；状态按当前实现修订。

1. 不以完全隐藏 Typst 语法为核心目标。
2. 完整所见即所得是长期目标，当前聚焦块显示源码。
3. CJK 输入与 CJK 字体/排版分别验收。
4. 当前聚焦粒度为整段/整块。
5. 原生源码输入与结构命令互补。
6. 单块原生、跨块自绘两种路径并存；交接由早期“越界即切换”修订为“松开、提交并等待匹配渲染”。
7. 无法结构化解析时保留原文；编译失败另走诊断与成功结果保留。
8. 语义与结构编辑是持续工作，不因采用原生源码而结束。
9. 声明导航、注释保留、公式编辑分别处理。
10. Spike 1 正面：原生聚焦/真实重编译可用；保留宽度对齐、不全选、Escape 提交三条修正。
11. 公式、引用及参考文献提高后续优先级，尚未交付专用交互。
12. 保留独立 Typst 源码编辑入口，入口形式可随 tab 收敛调整。
13. Spike 3 选择失焦后分块；不继续打磨逐空行立即分块的版本。
14. 使用端→定义端采用聚焦块上方引用清单，已实现变量/标签跳转；不包含 `#set` 影响范围或反向使用清单。
15. 顶层空行与表格参数内空行不能同等处理；括号深度分块已修，三反引号围栏仍待做。
16. 聚焦几何应在切换前取得；跨块拖拽交接需等待成功渲染。真实测试曾推翻仅凭模拟后端得到的初版结论。
17. 未聚焦真实排版与聚焦源码输入是当前机制，不能表述为所有时刻都在最终结果内编辑。
18. 已声明变量/函数补全**仅有设计**：聚焦时批量获取可见 `#let`/`#import` 绑定，输入时前端按前缀过滤；代码上下文复用语法信息，不用正则猜测。候选显示名称和定义位置，不包含标准库、字体、符号及包名。菜单用 textarea 光标测量定位，与未来斜杠菜单共用测量；打开时优先处理 Up/Down/Enter/Escape，不让跨块导航抢键。现有“实际引用清单”接口尚未因此自动具备全部可见绑定。
19. 跨块撤销已实现；原生历史优先，应用历史采用差异/结构快照。最新剪切/粘贴独立入历史；尚无内存上限。
20. Live 斜杠菜单降为待定，v0.1 不做；源码输入目标下不能沿用“完全免语法”的旧理由。
21. 自动保存已实现，直接写已有原文件；新增草稿及组合保护仍需原生重验，独立恢复文件未实现。
22. 编译失败采用保留上次成功渲染与错误块诊断。临时修补、自动改语法、整篇切源码、fork evaluator 及 typed holes 均未采用，原因见 [Phase 4](phase4-product-validation.md)。
23. 2026-09-18 曾依据后端耗时关闭长文档专项；2026-09-19 前端问题和 2026-10-22 用户反馈表明证据不足，现重新开放整体预览性能，见 [性能分析](preview-performance.md)。

下一步：先完成退出、裁剪、草稿/剪贴板及编译错误的原生回归，再推进 tab 收敛；同时测量真实更新路径。目标用户验证独立推进，随后落实学术能力与界面范围。暂停旧 PM 编辑面独有的细节打磨、对所有节点逐一设计专属控件，以及没有明确问题的持续竞品扩展调查。
